# Autonomous income loop

The owner has authorized implementation and parallel work: move the existing project toward real income and automate its operation. Preserve fictional adult personas, their identity checks, auditable evidence, and bounded costs. Existing S24 native Go/QNN media and Azure model endpoints are the production compute lanes. The uploaded guide supplies experiment hypotheses, not verified earnings.

## Delivery

Connect existing MoA/RAG planning and asset generation to a restart-safe scheduler, real platform confirmation, cumulative outcome ingestion, authenticated payments, and learning closure. A persistent runtime performs bounded ticks and can be supervised on the phone or an Azure worker. It acts on a configured offer and accounts, reuses the existing ledger, and exposes exact blockers.

The first automatic content lane is Instagram still images, using the existing image generator. Other adapters accept reviewed compatible videos. Generated releases can use the owner's explicit `auto_approve` configuration only when identity and quality are scored and passed and commercial copy passes validation. Manual review remains available. The model cannot alter release authorization, budget, or scoring policy.

## Contracts

- Queue records and receipts survive restarts. Workers atomically claim posts, back off retryable errors, resume known provider operations, and hold ambiguous submissions for reconciliation. A confirmed post ID and real permalink are required before ledger publication.
- Social cumulative snapshots record only increments, with persisted watermarks and conflict detection. Missing platform data stays absent/zero, never a manufactured performance estimate.
- Stripe webhook signatures are verified on raw bytes. Only confirmed paid USD transactions enter earnings; test transactions remain separate. Deduplication spans both webhook IDs and payment identifiers. Refunds and disputes subtract confirmed amounts, unmatched attribution is recoverable, and incomplete fees or payout data remain explicit.
- Runtime generation reserves a configured conservative cost before model calls, obeys daily and monthly ceilings, and retains the reservation after failure. It limits batch frequency and backlog, scopes candidates to the configured campaign, and refuses silent provider fallbacks.
- Publishing, metrics, commerce retry, and settlement continue even when new generation is disabled. Settlement requires published variants and the configured observation window plus exposure. Revenue comes from commerce events, never clicks or projections.
- Recommendations retain the recorded reason, supporting observations, evidence strength, and reversal condition. Deep RL remains behind the existing experience gate.

## Evidence

Regression tests exercise queue restart, stale/concurrent workers, async platform status, media bytes, cumulative metrics, signed payments, duplicate payment notifications, partial refunds, test isolation, runtime ceilings, release gates, restart cadence, and learning closure. Offline tests demonstrate implementation behavior. Live generation, post, purchase, fulfillment, and positive net income require external receipts and are reported separately.
